# F2a: convert on the native grid

**Date:** 2026-11-03 · **Branch:** `feat/f2-convert` · **Status:** REVIEWED (stress-test rounds 1-3 applied)
**Parent plan:** `docs/plans/2026-11-03-rt-dataprep/phase1.md` (F2) · **Decisions/legacy facts:** `proposal.md` beside it

## Background

F1 (`organize`, PR #6) turns a DICOM_Transport export, which is flat (`<root>/<mrn>/*.dcm`, no sub-folders), into
`<out>/<patient>/fx_<n>/` (one folder per RTPLAN) plus `misc_files/`. F2 turns that into NIfTI files. Decisions
made in the F2 interview (2026-11-03):

- F2 is split: **F2a** (this spec) writes everything on the native grid. **F2b** (a later `/dev`) adds
  `preprocess.py`, the `--legacy-rnt` preset (without ahe, honest names) and A2.5/A2.6. OSC parity waits for F2b.
- The goal is **not** to recreate the RNT data layout. `--flat` and A2.7 are dropped. This supersedes proposal.md
  decision 7 and the flat parts of phase1.md F2.
- Exports are not necessarily fractions, so plan folders are named **`plan_<n>`**, not `fx_<n>`. This changes F1's
  output naming in this feature, and plan metadata (fractionation and so on) goes into a file F3's manifest reads.
- Non-registered images go to `<patient>/images/`. A registered image goes into the plan folder of each planning
  CT it is registered to (copied when there are several).
- Hardening issue #7 is folded in. AHE is out (#16). Imaging-only patients are out (#17).

## Problem

The step from sorted DICOM to ML-ready files (CT, dose in Gy, structure masks, applicator points, other imaging)
exists today only as uncommitted legacy code. That code picked "the CT in the folder", never scaled dose to Gy, and
collapsed or linearly interpolated masks. Consumers are rnt_transformer and vision_transformer, through F3's
manifest.

## Constraints

- **Clinical output.** CT, dose and masks become training labels and dose analysis. A wrong CT pick, a dose in the
  wrong units, a gap in the CT or an empty mask is a silent wrong value. Everything in this path gets full rigor and
  a test, and an unexpected state refuses the case instead of guessing.
- **PHI.** Log lines, exception messages and refusal reasons are fixed strings: no PatientID, name, date, path,
  UID or tag value. Every third-party call (pydicom, SimpleITK, DicomRTTool) runs inside a wrapper that captures
  warnings, stdout/stderr **at the file-descriptor level** (`os.dup2`; SimpleITK/ITK/GDCM write from C++, which
  `redirect_stderr` misses; plus `sitk.ProcessObject.SetGlobalWarningDisplay(False)`) **and log records**. The
  fixed-reason error is raised after the `except` block has exited (a flag set inside it), never inside it: `from
  None` alone still leaves the original exception, path included, on `__context__` (DicomRTTool logs `Failed on <path>` with a traceback even with
  `verbose=False`, and an unhandled logger falls back to printing to stderr). The wrapper raises a fixed-reason
  error from None (vault: `third-party-loader-errors-and-warnings-embed-phi-paths`,
  `pydicom-validates-lazily-on-first-tag-access`). Free text (SeriesDescription, RTPlanLabel), dates and UIDs go
  only into `series.csv` files under the output root.
- **Data safety.** The organized tree is only read. Each patient's output is built under a hidden partial name and
  renamed into place at the end. A crash never leaves a folder that a rerun would skip as done
  (vault: `record-completion-at-outcome-not-intent`), and a stale partial from an earlier crash is removed first.
- **Tests.** Synthetic DICOM from `tests/synthetic_dicom.py`, extended with a general ROI writer: closed-planar
  ROIs on the CT's frame of reference, POINT, empty and BRACHY_CHANNEL ROIs, mixed in one RTSTRUCT; and `write_reg`
  gains a RegistrationSequence with per-frame matrices. New tests use
  IDs without digits or underscores (e.g. `SYNTHETICPTA`), so the global pre-commit MRN rule never trips and no
  `--no-verify` is needed.
- **Dependencies.** Add `SimpleITK` and `DicomRTTool==6.2.0`. No `mclahe`, torch or torchio.
- **FHIR surface:** not applicable (files only). **Safety class:** the outputs are training labels, not
  treatment, but they are treated as clinical output (see above).
- **Commit gate** (`~/.claude/hooks/pre-commit.sh`, added lines only). No added line may put `mrn`/`patient_id`
  next to a run of 6-10 digits (pass dates through a variable defined on its own line). No added line may access
  an underscore-prefixed attribute of another module, so helpers shared across modules are public (`quiet_read`, not `_read`).
- **Compliance rule update.** The `phi` rule in `project-profile.yml` is reworded: `series.csv` files under the
  output root carry per-file metadata (sanitized id, dates, plan label, SeriesDescription, UIDs). Like the
  reports, they are never committed, and log lines and exceptions still carry none of it.

## Premises (confirmed)

- The case unit stays one RTPLAN. Convert follows the UID chain RTPLAN → RTSTRUCT → CT series, never "the CT in the
  folder". A plan folder can hold several CT series, several RTSTRUCTs and registered MR/PET.
- Every CT/MR/PT image series of a patient is written once per destination, on its own grid, with no resampling.
  Registration into the CT frame stays deferred (#1).

## Chosen approach

Port the validated rnt functions (`read_dicom`/`_read`, `read_ct_series`, `read_rtdose`/`_convert`,
`resample_dose`, `write_atomic`) and add the one missing piece, RTSTRUCT → masks via DicomRTTool. The DicomRTTool
call sequence was checked on synthetic data in the stress test: a 500-voxel cube gave exactly 500 voxels, and two
overlapping ROIs each kept 500 with `arg_max=False`. Rejected: rt-utils (legacy used DicomRTTool), writing a
rasterizer, and running convert straight on `<mrn>/*.dcm` (organize stays a separate step, user decision).

### organize changes (F1)

- Plan folders are `plan_<n>` (same order as today's `fx_<n>`). The report column `fx_count`, the `PatientRow.fx`
  field and the CLI help text are renamed to match (`plan_count`, `plans`).
- **#7:** the resolved RTSTRUCT file is always added to its plan folder, even when it sits in a different study from
  the CT. phase1.md F1 step 3 gets the same wording.

### convert

`convert(org_root, out_root, *, exclude_models=('Acuity',)) -> ConvertReport` (F2b adds `steps=`), CLI `python -m rt_dataprep convert <org> <out>`. `out_root` inside
`org_root` is refused before anything is written. For each `<org_root>/<patient>/` whose name does not start with
`.` (an interrupted organize leaves `.<patient>.partial/`, which is never converted):

`format_name(s)` is `s` lowercased with every non-alphanumeric character removed (legacy `utils.py`).

1. **Read headers** of every file in its `plan_<n>/` folders and `misc_files/`. In a plan folder, any unreadable
   file refuses that plan, since it might be a missing CT slice. In `misc_files/` it is counted and skipped.
2. **Per plan** (`plan_<n>/`):
   1. **Assemble.** The folder must hold exactly one RTPLAN. Resolve its RTSTRUCT
      (`ReferencedStructureSetSequence[0]`) and the one CT series that RTSTRUCT references. A broken chain, or a
      chain resolving to anything other than one CT series, refuses the plan.
   2. **CT.** The planning CT must be one volume: one orientation and image size, no duplicate slice positions,
      uniform spacing along the normal (tolerance as rnt's `ORIGIN_ATOL_MM`), no sideways offset between slices (a
      gantry tilt or shear), at least two slices, and an axial slice normal (|n_z| ≥ 1 − `DIRECTION_ATOL`: DicomRTTool
      6.2 picks a contour's slice by patient z alone, so a coronal or sagittal CT puts every contour on slice 0). Otherwise the
      plan is refused. Every SOP listed in the `ContourImageSequence` of the RTSTRUCT's `RTReferencedSeriesSequence`
      item for the planning CT series (only that item; an RTSTRUCT may also reference MR slices) must be in the plan
      folder, otherwise the plan is refused, since a missing end slice passes the spacing check. An item with no
      `ContourImageSequence` also refuses the plan, since the check cannot run (user decision). It is read as float32 HU (`SetOutputPixelType(sitkFloat32)` before `Execute`, so slices with
      different rescale slopes are not quantized; the same reader is used for every series), files sorted along the slice normal → `planning_ct.nii.gz`.
   3. **Dose.** Candidates are the RTDOSEs whose `ReferencedRTPlanSequence` names the plan. Precedence:
      exactly one PLAN → use it; else exactly one FRACTION → use it; else, if every candidate is BEAM, sum them; no
      candidate → the plan is written without dose. Anything else refuses the plan: two PLANs, two FRACTIONs with
      no PLAN, or only other types (BRACHY, MULTI_PLAN, …). Every dose that is used must pass the ported checks
      (`DoseUnits` GY, `DoseType` PHYSICAL, uniform frame offsets, with BEAM added to the allowed summation types)
      and share the CT's `FrameOfReferenceUID`. Values are `pixel × DoseGridScaling` in Gy, each linearly
      resampled onto the CT grid (0 outside), then summed → `dose.nii.gz`.
   4. **Masks.** Before the call, list the kept ROIs: everything except POINT ROIs (`ContourGeometricType` POINT
      on every contour), ROIs with no contour data, names containing `dose` (case-insensitive) and applicator
      channels. Their `format_name` values must be non-empty and unique. A kept mask or applicator ROI whose
      `ReferencedFrameOfReferenceUID` is not the planning CT's frame refuses the plan (no registration in F2a). Hard-link the planning CT slices and the
      RTSTRUCT into a temp folder inside the patient's partial folder (so stale-partial cleanup also removes it), falling back to copying when linking fails (e.g. across
      filesystems). Run DicomRTTool 6.2 in one pass inside the wrapper: `DicomReaderWriter(arg_max=False,
      verbose=False)`, `walk_through_folders`, `set_contour_names_and_associations(contour_names=<kept>)`,
      `set_index(<index whose SeriesInstanceUID is the planning CT>)`, `get_images_and_mask()`. Then **verify**,
      because DicomRTTool fails silently with all-zero masks:
      - exactly one index carries the planning CT UID, and it has the RTSTRUCT linked;
      - every kept ROI is in `mask_dictionary` (keyed by `ROIName.lower()`; DicomRTTool lowercases names) and has
        at least one voxel set;
      - each mask's size, origin, spacing and direction equal the CT's (`ORIGIN_ATOL_MM`, `DIRECTION_ATOL`);
      - each mask has voxels on exactly the CT slices its non-POINT contours lie on (each contour's vertices mapped
        through the CT's full geometry and rounded to one slice index). This checks DicomRTTool's placement
        independently: a z-only slice lookup or a contour off the CT snapped onto an end slice refuses.
      Any failure refuses the plan. Each mask is written as {0, 1} uint8 → `<format_name(ROIName)>.nii.gz`. The temp
      folder is removed in every outcome.
   5. **Applicators.** ROIs that are `OPEN_NONPLANAR` or have `RTROIInterpretedType == BRACHY_CHANNEL` are each
      written with `np.savetxt(<final name>.nii.gz, points, fmt='%.4f')`, all contour points (N, 3) in patient mm.
      numpy gzips because of the suffix, so the temp name must also end `.nii.gz`. The file name is the
      alphanumeric characters (case kept: `Ring`, `Tandem`, `Needle1`) of the `SourceApplicatorID` of the RTPLAN
      channel whose `ReferencedROINumber` is that ROI, or of the ROI name when no channel names it. An empty name
      refuses the plan.
   6. **Name clashes.** Two outputs of one plan that map to the same file name, compared case-insensitively,
      refuse the plan. Nothing is overwritten.
3. **Other series.** Every CT/MR/PT series of the patient that is not the planning CT of a converted plan is a
   candidate, from the plan folders and `misc_files/`, deduplicated by `SeriesInstanceUID`. A refused plan's CT is
   a candidate like any other, so no imaging is lost. A patient with no `plan_*` folders still gets `images/`.
   Localizers (`ImageType` LOCALIZER) and excluded models (organize's `exclude_models`) are left out. A series is
   **registered** to a converted plan (user decision, frame level):
   - it shares the planning CT's `FrameOfReferenceUID` (`reg_matrix` = `identity`), or
   - some REG of the patient holds, in its `RegistrationSequence`, one item for the planning CT's frame and one for
     the series' frame. Each item's rigid `FrameOfReferenceTransformationMatrix` M maps that item's frame into the
     REG's own frame (PS3.3 C.20.2.1.1), so `reg_matrix` = inv(M_ct) · M_series (series frame → CT frame). A REG
     whose own `FrameOfReferenceUID` is the CT's frame counts as having an identity CT item even when it omits one.
     An item whose `MatrixSequence` does not hold exactly one rigid matrix, or a missing matrix, leaves `reg_matrix`
     empty; the series is still placed. When several REGs qualify, the first by
     SOPInstanceUID is used.
   A study-level link with no frame match does not count. Placement runs only after every plan of the patient has
   its outcome, because "converted plan" and "refused CT" both depend on it.
   - Registered: written into each such converted plan folder as `series_<Modality>_<k>.nii.gz`.
   - Not registered to any converted plan: written once into `<patient>/images/` with the same naming.
   - k counts from 1 per folder and modality, in order of `(SeriesDate, SeriesTime, SeriesInstanceUID)`.
   - A series that fails the one-volume check or fails to read is skipped and counted. It does not refuse anything.
4. **series.csv** in each plan folder and in `images/`, one row per written file. Columns:
   - `file`, `kind` (ct, dose, mask, applicator, series), `modality`, `series_description`;
   - `series_instance_uid`, `study_instance_uid`, `frame_of_reference_uid`, `series_date`;
   - `roi_name`, `dose_summation_type`;
   - `reg_matrix`: 16 space-separated values (row-major) mapping the series frame to the planning CT frame,
     `identity` for the same frame, empty when no rigid matrix exists;
   - plan columns, filled in plan folders: `rtplan_uid`, `rtplan_label`, `rtplan_date`, `fractions_planned`
     (`FractionGroupSequence[0].NumberOfFractionsPlanned`).

   F3's manifest aggregates these files. `series.csv` is added to `.gitignore`.
5. **Layout and atomicity.** The output is `<out_root>/<patient>/plan_<n>/` and `<out_root>/<patient>/images/`. A
   patient is built in `<out_root>/.<patient>.partial/` and renamed into place. A patient whose output folder
   already exists is skipped. A refused plan leaves no `plan_<n>/` folder; the patient's other plans and images are
   still written.
6. **Report.** `convert_report.csv` in `out_root` has one row per plan, one per patient for `images/`, and one
   patient-level row when the whole patient is skipped or fails with an `OSError`.
   Columns: patient, folder, outcome (converted/skipped/refused), reason constant, files written (`;`-joined
   names) and skipped-series count.

## Acceptance criteria

- **A2.0 (organize)** Plan folders are named `plan_<n>`. The F1 tests pass with the new names.
- **A2.1** A synthetic plan folder gives `planning_ct.nii.gz` equal to the source CT (spacing, origin, direction,
  values) and `dose.nii.gz` equal to stored value × `DoseGridScaling`, resampled onto the CT grid.
- **A2.1b Dose rule.**
  - PLAN + BEAM → the PLAN dose. PLAN + FRACTION → the PLAN dose. One FRACTION → used.
  - Two BEAM → their sum on the CT grid.
  - Two PLAN, or a single BRACHY → refused.
  - No RTDOSE → converted with no `dose.nii.gz`.
  - `DoseUnits` not GY, or a used dose whose frame of reference differs from the CT → refused.
- **A2.1c** A planning CT with a missing middle slice is refused, and so is one missing an end slice that the
  RTSTRUCT references. An unreadable file in a plan folder refuses that
  plan.
- **A2.2** A cube ROI gives a binary mask on the CT grid whose voxel count equals the cube volume (±1 slice edge).
- **A2.2b** Two overlapping ROIs both keep their full voxel count.
- **A2.2c** A kept ROI whose mask comes back empty from DicomRTTool refuses the plan.
- **A2.3** A BRACHY_CHANNEL ROI gives `<letters>.nii.gz` that `np.loadtxt` reads back into its contour points
  (tolerance 1e-4), named from the plan's `SourceApplicatorID`. POINT ROIs, empty ROIs and names containing `dose`
  produce no file. ROIs whose names clash, or reduce to an empty name, refuse the plan.
- **A2.4** An MR whose frame a REG registers to the planning CT's frame leaves the planning outputs unchanged and is
  written into the plan folder as `series_MR_1.nii.gz` on its own grid. Its `series.csv` row carries its
  SeriesDescription, UIDs and a `reg_matrix` that maps a named MR-frame point to its known CT-frame coordinates
  (within 1e-6). The fixture places the MR frame at a known translation (+10 mm in x) of the CT frame, and its
  matrices are built from the standard's wording (item frame → REG frame, M11..M14 first), not from the spec's
  formula. The check runs for a REG in the CT frame and for one in the MR frame. A REG item with two matrices
  gives an empty `reg_matrix`. An MR whose study a REG names but whose frame it does not
  goes to `images/`.
- **A2.4b** Two CT series in one study, on different frames with no REG: the one the plan's RTSTRUCT references is
  `planning_ct.nii.gz`, and the other goes to `<patient>/images/series_CT_1.nii.gz`.
- **A2.4c** An MR registered to two plans' CTs is written into both plan folders. An MR in `misc_files/` with no
  registration is written once to `images/`. A refused plan's CT goes to `images/`. A patient with only
  `misc_files/` gets `images/`. An org tree holding `.<patient>.partial/` does not convert it.
- **A2.4d** The plan folder's `series.csv` carries `rtplan_label`, `rtplan_date` and `fractions_planned`.
- **A2.8** A plan referencing a missing RTSTRUCT is refused. The report row carries the reason constant, and no
  `plan_<n>/`, partial or temp folder is left behind.
- **A2.9 (#7)** An RTSTRUCT stored in a different study from its CT is organized into the plan folder and converts.
- **A2.10 PHI** (captured with pytest `capfd`, so C-level output counts). Two cases: a CT slice with a readable header and truncated pixel data, and a broken RTSTRUCT that
  DicomRTTool fails on. Each refuses with a fixed reason. Neither the exception (message, `__cause__`,
  `__context__`) nor any captured log record, warning or stdout/stderr output contains the synthetic patient id,
  the tmp path or a UID.
- **A2.11** After a run the organized tree is byte-identical (hash of every file), and a rerun reports every
  patient as skipped.
- **A2.12** `python -m rt_dataprep convert` runs end to end on a synthetic tree and writes `convert_report.csv`.

## Failure handling

- Per-plan problems (broken chain, CT check, dose rule, mask verification, DicomRTTool failure, unreadable file, name
  clash) raise `CaseRefused(reason)` with a fixed constant. The plan is reported as refused, and the run moves on.
- An unreadable or non-volume non-planning series is skipped and counted, not refused.
- An `OSError` on the output side refuses the patient with a fixed reason and removes the partial folder. Anything
  else propagates.
