# Spec: optional HU window clip for CT (#373)

## Problem

The only CT intensity step is `--rescale`, `(HU + 1024) / 4096` with no clip. Published RT work clips CT to a HU window
first (EBRT dose about [-1024, 1500]; segmentation windows such as [-1000, 1000], [-500, 500], [-175, 250]), so training
code clips today. Mixed 12-bit and 16-bit cohorts make this worse: convert already writes every CT in HU, but an
extended-HU (16-bit) CT runs past 3071 HU, so `--rescale` gives values above 1 for those CTs and stays in [0, 1) for the others.

## Behaviour

- `PreprocessSteps.hu_window: tuple | None = None`, `(LO, HI)` in HU. CLI: `--hu-window LO HI` (two floats).
- Validation: LO and HI are finite and LO < HI. Otherwise `ValueError(REASON_HU_WINDOW)`, a fixed string constant, raised
  by `preprocess()` before any output is written. The CLI lists the constant among its known refusals, so it prints as a
  refusal, not as an unexpected error.
- The window is a **step** of its own: it counts toward "at least one step is on", so it can run alone. It writes the
  `huwindow_` prefix. Name order, newest first: `reshape_ resample_ ahe_ rescale_ huwindow_ initialresample_`.
  `STUDY_FILE` matches the new prefix.
- `STUDY_FILE` has two consumers, `series_id` in preprocess (study folder rows) and `manifest.py` (manifest row id);
  both must recognise a `huwindow_` file.
- **CT only**: the planning CT, study CT series and registered CT series in a plan. MR and PT skip it, as they skip
  `--rescale`: `preprocess_series` turns off both `rescale` and `hu_window` for a non-CT series, and its
  "any step on" check (like the one in `preprocess()`) lists `hu_window`, so a run whose only steps are the window and/or
  rescale refuses an MR/PT study series with `REASON_NO_SERIES_STEPS`. Dose, masks and other kinds never get the prefix.
- **Order**: planning and study CT: initial resample → clip → rescale → ahe → final resample → reshape. Registered CT in a
  plan: clip → rescale → ahe → one resample onto the final CT (`process_series` takes the window as a new argument).
- The clip is a voxelwise clamp to [LO, HI] in float32; the output is float32 (like every other step), geometry unchanged.
- Fill values: only two follow the window. Reshape pads with the minimum of the CT entering reshape (already the rule,
  so the clipped minimum). A registered CT that is neither rescaled nor equalized fills outside its FOV with the minimum
  of the clipped native image, not the raw one. Every resample keeps filling with 0 as today, so with a resample step
  the region outside the original CT is 0, which may lie outside [LO, HI]; `--series-fov-mask` marks that region.
- The window is an intensity step, not a geometric one: `--allow-crop` with only intensity steps (window, rescale, ahe)
  still refuses with `REASON_ALLOW_CROP_STEPS`.
- A registered MR/PT series in a plan folder is treated as in a rescale-only run today: no clip, no prefix.
- `--rescale` is unchanged. A mixed 12/16-bit cohort uses `--hu-window -1024 3071 --rescale` to get [0, 1] for every CT.
- No provenance beyond the prefix (same as `--new-spacing`, the AHE options; run provenance is #5).

## Acceptance

1. Planning CT with `hu_window=(-100, 200)` alone: output `huwindow_<ct>` is float32, equals `np.clip` of the input
   voxels (exactly, in float32), so min ≥ -100 and max ≤ 200, and has the same geometry.
2. With `--initial-resample --hu-window LO HI --rescale` the output name is `rescale_huwindow_initialresample_<ct>`
   and its values match `(clip(resampled, LO, HI) + 1024) / 4096` with `np.allclose(rtol=0, atol=1e-6)`.
3. Study folder: the CT series gets the prefix and the clip; an MR series in the same run with a geometric step gets
   neither (values identical to a run without the window); with `--hu-window` alone the MR series is refused with
   `REASON_NO_SERIES_STEPS`. `manifest` over that output lists the windowed CT series under its usual id.
4. A registered CT series in a plan is clipped before its resample, and its outside-FOV fill (no rescale, no ahe) is
   the clipped minimum.
5. `hu_window` with LO ≥ HI, NaN or inf raises `REASON_HU_WINDOW`; the CLI given `--hu-window 200 100` prints it as
   a refusal (exit code as for other refusals).
5b. CLI happy path with a negative LO: `preprocess ... --hu-window -1024 1500` runs and writes `huwindow_<ct>` clipped
   to [-1024, 1500].
5c. `hu_window` with `allow_crop` and no geometric step raises `REASON_ALLOW_CROP_STEPS`.
6. Dose and mask file names and values are unchanged by `hu_window`.
7. Docs and help: every README place that lists the steps, prefixes, CT/MR step rules, errors or PreprocessSteps fields
   gains the window; a note explains the 12/16-bit use. The `--rescale` help text and the preprocess module docstring
   name the new order.

## Deferred

- A default window, or a window-to-[0, 1] rescale variant.
- Recording LO/HI in a run config file (#5).
- NaN voxels through the clamp (SimpleITK's clamp behaviour on NaN is unchecked).
- A malformed `hu_window` from the Python API (wrong length or type) beyond the finite / LO < HI check.
- A run-log warning when `--rescale` sees CTs above 3071 HU without a window.
