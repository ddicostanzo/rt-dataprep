# Closure evidence: preprocessing coverage and allocation failures

## Issue #51

The earlier B8 pass already supplied the flipped/oblique TorchIO comparisons, CT-first ordering, exact half-voxel
boundaries, weak-reference memory-release checks, and corrected converted-tree parity wording. TorchIO comparisons
remain optional and skip when that comparison package is unavailable; they are not reported as executed here.

The remaining partial-mask-loss case is now a runtime policy option with regressions in `tests/test_mask_retention.py`:

- A thin 0.5 mm mask can retain a single target voxel after resampling yet retain only 24.0% of its input physical volume
  under nearest-neighbor interpolation (about 3.0% under fractional linear interpolation). The existing empty-mask guard
  cannot catch it because that one voxel remains.
- `min_mask_retention` / `--min-mask-retention` lets the caller supply the minimum accepted output/input volume fraction.
  There is no invented clinical default. With the option off, compatibility is preserved. With it on, a failing plan is
  refused and cleaned up, the report has a fixed reason, and a valid sibling is kept.
- Physical voxel volume is included, so eight half-millimeter voxels count as one cubic millimeter, not eight times the
  volume of one 1 mm voxel. Linear masks integrate fractional values in both input and output. Equality at the threshold
  is accepted within relative tolerance 1e-6; invalid limits are rejected before writing output.
- The guard is a volume-retention check, not a proof of contour fidelity or clinical acceptability. OSC data can guide the
  caller's threshold without keeping the test-coverage issue open or changing default pipeline behavior.

## Issue #53

`tests/test_dicom_io.py` covers typed MemoryError, ENOMEM, recognized alternative ITK/C++ RuntimeError messages, ordinary
input errors, and failing exception stringification. `tests/test_series.py` covers CT and dose allocation failures at
conversion level: the run aborts, reports are flushed, partial output is removed, and messages/chains do not escape.

Known alternatives such as `std::bad_alloc` and `Out of memory` no longer become per-file unreadable refusals. This does
not claim to classify every hypothetical future library message. Real-data resource profiling remains tracked by #47.
